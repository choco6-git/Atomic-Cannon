# Network Lobby Room List Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show open network rooms on the entry screen so a second player can click one to join, instead of typing its code.

**Architecture:** A global `Lobby` Durable Object (singleton, like `Stats`) holds one small listing per open room. Each `Room` publishes its listing whenever lobby state changes and on a 20 s alarm heartbeat; listings expire after 60 s. `GET /api/rooms` serves the list; the client polls it every 4 s while the entry screen is visible. Pure logic (validate, expire, sort, "is this room listable") lives in `src/net/roomList.ts` and is shared by worker and client.

**Tech Stack:** TypeScript, Cloudflare Workers + Durable Objects (`wrangler`), Preact + `@preact/signals`, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-13-room-list-design.md`

## Review Focus

- The host leaves a lobby that still has players: the room stays listed, now under the new host's name (Task 3 test `host handoff keeps the listing`).
- A full room (players == max) loses a player: it reappears in the list (Task 3 test `full room reappears when someone leaves`).
- Nothing has ever been published: `GET /api/rooms` returns `{"rooms": []}` with 200, not an error (Task 2 test `empty lobby lists nothing`).
- A room built by a different app version is shown but not joinable (Task 1 test `isJoinable rejects a different appVersion`).
- A hostile or malformed upsert (bad code, 10 000-char name, negative or NaN numbers, non-object body) is rejected or clamped and never stored as-is (Task 1 `sanitizeListing` tests, Task 2 test `rejects a malformed upsert`).

**Files:**
- Modify: `worker/Room.ts` (`Env`; new `publishListing`; calls in `onHello`, `onSettings`, `onStart`, `dropPlayer`; lobby branch at the top of `alarm()`; a `m_lastListing` member)

**Interfaces:**

- Produces: `Room` now reads an **optional** `env.LOBBY: DurableObjectNamespace | undefined` (add `LOBBY?: DurableObjectNamespace` to its local `Env`; store the constructor's `env` instead of discarding it). `private async publishListing(s: RoomState, force = false): Promise<void>`:
  - computes `listingFor(s)`; serialises it; skips when equal to `m_lastListing` unless `force`;
  - sends `upsert` (with the listing) or `remove` (with `{code: s.code}`) to the `global` Lobby stub; every error is swallowed;
  - only while `s.phase === 'lobby'`: when the listing is non-null arms `setAlarm(Date.now() + HEARTBEAT_MS)`, otherwise `deleteAlarm()`. It never touches the alarm in other phases (the AFK turn alarm owns it there).
